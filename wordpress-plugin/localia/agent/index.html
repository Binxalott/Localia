How Localia works

      
    
        
  1. Your website or cron job puts a prompt into the Localia queue on your server.
    2. 
        
  2. This page checks the server every few seconds/minutes, signing each request with your shared secret.
    3. 
        
  3. The server hands over the next prompt as JSON. This page sends it to the LLM running on this PC.
    4. 
        
  4. The LLM's answer goes back to the server as JSON. Your app reads it from the queue (or gets a webhook).
    5. 
      

      
Because this PC always makes the outgoing request, your home router, firewall, NAT and changing IP address don't matter. Nothing on this PC is exposed to the internet.


      
Setting up the local LLM

      
Ollama

      
Install from ollama.com, then pull a model, e.g. ollama pull llama3.1:8b. Ollama allows pages on http://localhost by default, so open this page with the included start script (not by double-clicking the file). If you open it any other way, allow its origin:

      
Windows (PowerShell):  setx OLLAMA_ORIGINS "*"     then restart Ollama
macOS:                 launchctl setenv OLLAMA_ORIGINS "*"   then restart Ollama
Linux (systemd):       sudo systemctl edit ollama  → add:
                       [Service]
                       Environment="OLLAMA_ORIGINS=*"
                       then: sudo systemctl restart ollama

      
LM Studio

      
Open the Developer tab, start the server (default port 1234) and switch on Enable CORS. Choose "OpenAI-compatible" here with base URL http://localhost:1234.

      
llama.cpp / vLLM / LocalAI / Jan

      
Choose "OpenAI-compatible" and enter the server's base URL. Make sure it sends CORS headers (llama.cpp's llama-server does by default).


      
Keeping it running

      
    
        
  • Leave this tab open. Browsers slow down timers in background tabs; Localia works around this, but a pinned tab or its own window is most reliable.
    • 
        
  • Stop the PC from sleeping (power settings), or tick "Keep the screen awake".
    • 
        
  • Tick "Start the agent automatically" and add the start script to your OS startup items for a hands-off setup.
    • 
      


      
Troubleshooting

      

        
bad_signature / unknown_agent
The agent ID or secret here doesn't match the server's config.

        
clock_skew
This PC's clock is more than 5 minutes off. Turn on automatic time sync. (Localia also corrects for it automatically.)

        
Could not reach the server
Check the address/port/path, that the server allows CORS (it does by default), and if you use https with a raw IP that the certificate is valid for it.

        
Could not reach Ollama / LLM
Is the runtime running? Is CORS allowed (see above)?

        
A job was blocked by the prompt guard
The job looked like an attack (for example "ignore your instructions" or "find wallet.dat"), so the AI never saw it. If you didn't send it, check your server and change the secret. If it was a normal job (for example a post about password safety), untick the matching category in Settings → Prompt guard.

        
agent_secret_not_configured
The server still has the placeholder secret. Put a real one (16+ characters) in its config.
